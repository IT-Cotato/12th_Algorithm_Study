## 분할 정복

### 01. “분할 정복” 이란?

- 큰 규모의 문제를 풀기 위해 하위 문제로 나누어 풀이하고 이들의 해답을 결합하여 최종 해답을 얻는 방법
- 문제를 가장 작은 단위의 문제로 분할한 후, 해당 문제들을 결합하여 부분 해답을 도출, 또 다시 부분 해답을 결합하는 과정을 통해서 최종적으로 큰 규모의 문제를 풀이
- 분할(Divide) → 정복(Conquer) → 병합(Combine) : 문제를 쪼개고, 하위 문제를 풀고, 결과를 합친다
    - Divide : 문제가 분할이 가능한 경우, 2개 이상의 문제로 나눔
    - Conquer : 나누어진 문제가 여전히 분할이 가능하면 다시 Divide 수행. 그렇지 않으면 문제를 품
    - Combine : 정복한 문제들을 통합하여 원래 문제의 답을 얻음
- 보통 구현은 재귀 + 병합
    - 하위 문제 풀이는 보통 재귀로, 마지막에 결과를 병합

### 02. 분할 정복 조건

- 문제의 분할이 쉽게 가능해야함
    - 주어진 문제를 작은 부분 문제들로 나눌 수 있어야함
- 하위 문제를 해결하는 방식이 상위 문제를 해결하는 방식과 동일해야함
    - 재귀적으로 동일한 방식을 통해서 문제를 해결하기 때문
- 부분 문제의 해결이 독립적이고 효율적이어야함
    - 하나의 부분 문제를 해결하는 과정이 다른 부분 문제의 결과에 영향을 주지 않아야함

### 03. 분할 정복 vs 동적 계획법(DP)

| 구분 | 분할 정복 (D&C) | 동적 계획법 (DP) |
| --- | --- | --- |
| 하위 문제 중복 | 거의 없음(또는 신경 안 씀) | 많음 → 메모이제이션/탭으로 한 번만 계산 |
| 하위 문제 독립성 | 독립적인 경우가 많음 (합칠 때만 상호작용) | 중복/의존 관계가 많음 |
| 결합(Combine) | 병합 단계가 핵심 (예: Merge Sort의 merge) | 보통 최적 부분구조를 이용한 전개/누적 |
| 대표 형태 | 재귀 + 병합 | 메모이제이션(Top-Down) 또는 탭(Bottom-Up) |
| 예시 | Merge Sort, Quick Sort, 이진 탐색, 최단 거리의 두 점(평면 최근접 쌍) | LIS, LCS, Knapsack, Fibonacci(중복해결), Edit Distance |
| 언제 쓰나 | 문제를 잘 쪼갤 수 있고 합치기가 명확할 때 | 부분 문제 중복이 심하고 최적 부분구조가 있을 때 |
