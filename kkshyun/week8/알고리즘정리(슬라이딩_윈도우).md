## 슬라이딩 윈도우(Sliding Window)

### 01. “슬라이딩 윈도우” 란?

- 1차원 배열/문자열에서 연속된 구간(부분 배열) 을 다룰 때 쓰는 기법
- 길이가 고정된 윈도우(구간) 을 잡아두고, 그 구간을 한 칸씩 오른쪽으로 밀어가며(slide) 값들을 갱신하는 방식
- 매번 새 구간을 처음부터 다시 계산하면 O(N·K)가 걸릴 일을, 앞에서 빠지는 값만 빼고 뒤에서 새로 들어오는 값만 더해서 → 한 칸 이동당 O(1)에 갱신 → 전체 시간 복잡도 O(N)
- 보통 길이가 K인 구간의 최대/최소/합/조건 만족 개수 같은 고정 길이 부분 배열 문제에 자주 사용

### 02. 슬라이딩 윈도우**의 작동 원리**

1. 초기 윈도우 설정
    - 길이가 K인 첫 구간 `[0 ~ K-1]`의 값으로 초기 합/상태를 만든다.
    - 예: `sum = arr[0] + ... + arr[K-1]`
2. 윈도우를 한 칸씩 오른쪽으로 이동
    - 다음 구간은 `[1 ~ K]`, 그다음은 `[2 ~ K+1]` … 이런 식으로 한 칸씩 오른쪽으로 미끄러지듯 이동.
    - 이때 매번 전체를 다시 더하지 않고:
        - 이전 구간에서 빠지는 맨 앞 원소를 빼고
        - 새로 포함되는 맨 뒤 원소를 더한다.
3. 조건 갱신
    - 각 위치마다 현재 윈도우의 합/최댓값/조건 등을 갱신하면서 정답을 갱신한다.
4. 배열 끝까지 반복
    - 윈도우의 시작 인덱스를 0 → 1 → 2 → … → `N-K` 까지 옮기며 반복
- 구현 예시
    - 길이 K인 연속 부분합의 최댓값

    ```c
    int[] arr = ...;
    int K = ...;
    
    // 1) 첫 윈도우 [0 ~ K-1]의 합 계산
    int sum = 0;
    for (int i = 0; i < K; i++) {
        sum += arr[i];
    }
    
    int max = sum;
    
    // 2) 윈도우를 한 칸씩 오른쪽으로 밀면서 갱신
    for (int i = 0; i < arr.length - K; i++) {
        // 왼쪽에서 빠지는 값은 빼고, 새로 들어오는 값은 더하기
        sum = sum - arr[i] + arr[i + K];
    
        if (sum > max) {
            max = sum;
        }
    }
    ```


### 03. 투 포인터와의 비교

- 공통점
    - 둘 다 1차원 배열에서 부분 배열을 이용해 O(N²)를 O(N)으로 줄이는 기법
    - 연속된 구간(부분 배열)을 유지하면서, 그 구간을 변경해가며 특정 조건을 만족시키는지 확인한다는 점에서 유사
- 차이점
    - 슬라이딩 윈도우
        - 부분 배열의 길이가 고정되어 있음
        - 윈도우 크기가 고정이므로, 보통 한 개의 시작 인덱스(또는 끝 인덱스)만 움직여도 윈도우를 정의할 수 있음
    - 투 포인터
        - 부분 배열의 길이가 가변적
        - 시작 포인터(left), 끝 포인터(right) 두 개가 모두 움직이면서 구간의 길이가 계속 변함
