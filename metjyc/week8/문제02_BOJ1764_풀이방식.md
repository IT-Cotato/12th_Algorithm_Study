# 📌 해시 함수(Hash Function) 알고리즘 정리 — BOJ 15829 (Hashing)

이 파일은 **문자열에 대한 해시 값을 계산하는 문제(BOJ 15829)** 를 풀기 위해 필요한 핵심 개념과 구현 아이디어를 정리한 문서다.  
해시 함수의 기본 개념부터, 왜 거듭제곱을 곱하는 방식이 필요한지, 그리고 실제 코드 구현 전략까지 모두 정리했다.

---

## 🔎 1. 해시 함수(Hash Function)란?

해시 함수는 **임의의 길이를 가진 입력을 고정된 길이의 숫자(정수)로 변환하는 함수**다.

특징은 다음과 같다:

- 입력은 무한하지만 출력은 유한하다 → **충돌 가능성 존재**
- 동일한 입력 → 항상 동일한 출력(**일관성 보장**)
- 보통 **검색·저장·인덱싱** 등에 활용

---

## 🔠 2. 문제에서 사용하는 해시 설계 방식

문자열은 모두 소문자(a~z)로 구성되어 있으므로 다음 매핑을 사용한다:

| 문자 | 숫자 |
| ---- | ---- |
| a    | 1    |
| b    | 2    |
| ...  | ...  |
| z    | 26   |

예:  
**"abba" → 1, 2, 2, 1**

---

## 🧮 3. 단순한 해싱의 문제점

가장 간단한 해싱 방식:

\[
H = \sum\_{i=0}^{L-1} a_i \mod M
\]

그러나 이 방식은 **순서를 고려하지 않기 때문에 충돌이 쉽게 발생**한다.

예)

- "abc" → 1 + 2 + 3
- "cab" → 3 + 1 + 2  
  둘 다 6 → **충돌 발생**

---

## 🔧 4. 개선된 해싱 — 다항식 롤링 해시 (Polynomial Rolling Hash)

문자의 **위치 정보를 반영**하기 위해 각 문자에 고유 계수를 곱해 준다:

\[
H = \sum\_{i=0}^{L-1} a_i r^i \mod M
\]

여기서:

- \( a_i \): i번째 문자의 수치값
- \( r = 31 \): 소문자 알파벳의 개수보다 큰 소수
- \( M = 1234567891 \): 큰 소수(충돌을 줄이기 위해 사용)

이 방식은 대표적인 **롤링 해시(rolling hash)** 로, 문자열 검색(KMP, Rabin-Karp 등)에도 사용된다.

---

## 🔢 5. 필요한 수학 개념 정리

### ✔ 1) 문자 → 숫자 변환 (ASCII 활용)

알파벳 소문자의 ASCII 값:

```
'a' = 97
'b' = 98
...
'z' = 122
```

따라서:

```
value = charCode - 96
```

### ✔ 2) 거듭제곱의 반복 계산

이 문제에서 i번째 문자는 \( r^i \) 를 곱해야 한다.

매번 `31 ** i` 를 계산하는 것은 비효율적이므로 아래와 같이 계산한다:

```
power = 1   // r^0
power = (power * r) % M  // 다음 루프에서 r^1, r^2, ...
```

### ✔ 3) 중간에 반드시 mod 연산해야 함

숫자가 커지기 때문에 매번 덧셈/곱셈 후 mod 수행:

```
hash = (hash + a_i * power) % M
power = (power * r) % M
```

---

## 🧠 6. 알고리즘 흐름 요약

1. `hash = 0`, `power = 1` 초기화
2. 문자열의 각 문자에 대해:
   - 문자 → 숫자로 변환
   - `hash += (문자숫자 × power)`
   - `power *= r`
   - 매 연산마다 `% M` 적용
3. 최종 hash 출력

시간 복잡도: **O(L)** (문자 길이 최대 50이므로 매우 빠름)

---

## 🧪 7. 예제 계산

### 예제: `abcde`

| 문자 | 값(a_i) | r^i    | a_i × r^i |
| ---- | ------- | ------ | --------- |
| a    | 1       | 1      | 1         |
| b    | 2       | 31     | 62        |
| c    | 3       | 961    | 2883      |
| d    | 4       | 29791  | 119164    |
| e    | 5       | 923521 | 4617605   |

합: **4,739,715**

## 🧑‍💻 8. Node.js 구현 코드 (백준 제출용)

```js
const fs = require("fs");

const input = fs.readFileSync(0, "utf8").trim().split("\n");

const L = Number(input[0]);
const str = input[1].trim();

const r = 31;
const M = 1234567891;

let hash = 0;
let power = 1;

for (let i = 0; i < L; i++) {
  const num = str[i].charCodeAt(0) - 96; // a=1, b=2...
  hash = (hash + num * power) % M;
  power = (power * r) % M; // 다음 r^i 값 계산
}

console.log(hash);
```

## ✔ 최종 요약

- 이 문제는 **롤링 해시** 개념을 활용한 문자열 해싱 문제이다.
- 각 문자를 숫자로 변환하고,  
  위치 i에 따라 31^i 값을 곱해 더하면 된다.
- 덧셈/곱셈할 때마다 modulo 연산을 수행해야 한다.
- 시간/공간 둘 다 매우 효율적인 방식이다.
