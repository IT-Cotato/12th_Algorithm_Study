# 🧮 BOJ 1931 - 회의실 배정 (Meeting Room Allocation)

---

## 📖 문제 설명

한 개의 회의실이 있다.  
이를 사용하고자 하는 `N`개의 회의에 대해,  
**회의가 겹치지 않게 하면서 사용할 수 있는 회의의 최대 개수**를 구하는 프로그램을 작성하시오.

- 회의는 한 번 시작하면 중간에 중단될 수 없다.
- **한 회의가 끝나는 동시에 다음 회의가 시작될 수 있다.**
- 회의의 시작 시간과 끝나는 시간이 같을 수도 있다. (즉, 시작하자마자 끝나는 회의도 가능하다.)

---

## 🧩 입력 형식

```
N
시작시간1 끝시간1
시작시간2 끝시간2
...
시작시간N 끝시간N
```

- `1 ≤ N ≤ 100,000`
- 시작 시간과 끝나는 시간은 `0` 이상 `2³¹ - 1` 이하의 정수이다.

---

## 🧾 출력 형식

```
최대 사용할 수 있는 회의의 개수
```

---

## 🧠 문제 접근

이 문제는 **Greedy Algorithm(그리디 알고리즘)** 으로 해결할 수 있다.

### 🔹 핵심 아이디어

> “가장 빨리 끝나는 회의부터 선택하면, 남은 시간 동안 더 많은 회의를 배치할 수 있다.”

즉,  
매 단계에서 **끝나는 시간이 가장 빠른 회의**를 선택하는 것이 전체적으로 최적의 해를 만든다.

---

## ⚙️ 알고리즘 설계

1. 모든 회의를 `[시작시간, 끝시간]` 형태로 저장한다.
2. 회의들을 **끝나는 시간 기준 오름차순**으로 정렬한다.
   - 만약 끝나는 시간이 같다면, **시작 시간이 더 빠른 회의**를 먼저 둔다.
3. 정렬된 순서대로 회의를 탐색하면서 다음을 반복한다.
   - 현재 회의의 시작 시간이 이전 회의의 종료 시간 이상이면(`start >= lastEnd`) → 선택
   - 선택했다면 `count++` 하고, `lastEnd`를 현재 회의의 종료 시간으로 갱신
4. 모든 회의를 탐색한 뒤, `count`를 출력한다.

## 💻 코드 (JavaScript)

```js
const fs = require("fs");

const input = fs
  .readFileSync(process.platform === "linux" ? "/dev/stdin" : "input.txt")
  .toString()
  .trim()
  .split("\n");

const N = Number(input[0]);
const meetingList = [];

// 회의 시간 입력 저장
for (let i = 1; i <= N; i++) {
  const [startTime, endTime] = input[i].split(" ").map(Number);
  meetingList.push([startTime, endTime]);
}

// 종료 시간 기준 정렬 (동률이면 시작 시간 기준)
meetingList.sort((a, b) => {
  if (a[1] === b[1]) return a[0] - b[0];
  return a[1] - b[1];
});

let count = 0;
let lastEnd = 0;

// 겹치지 않는 회의 선택
for (const [start, end] of meetingList) {
  if (start >= lastEnd) {
    count++;
    lastEnd = end;
  }
}

console.log(count);
```

## ⏱️ 시간 복잡도 분석

| 단계      | 연산                | 시간 복잡도    |
| --------- | ------------------- | -------------- |
| 입력 처리 | N개의 회의 입력     | O(N)           |
| 정렬      | 종료 시간 기준 정렬 | O(N log N)     |
| 탐색      | 한 번의 선형 탐색   | O(N)           |
| **총합**  |                     | **O(N log N)** |

> 💡 N = 100,000 이어도 충분히 1초 이내에 동작한다.

## 🧾 알고리즘 요약

| 항목               | 내용                                         |
| ------------------ | -------------------------------------------- |
| **문제 유형**      | 그리디 알고리즘 (Greedy Algorithm)           |
| **핵심 기준**      | “빨리 끝나는 회의를 먼저 선택”               |
| **선택 조건**      | `start >= lastEnd`                           |
| **정렬 기준**      | 끝나는 시간 → (동률 시) 시작 시간            |
| **시간 복잡도**    | O(N log N)                                   |
| **대표 예시 문제** | 활동 선택(Activity Selection), 거스름돈 문제 |
